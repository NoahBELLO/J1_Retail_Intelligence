==================================================
CE QU'ON EN RETIENT
==================================================

1. Etat du systeme :
   - Safe mode OFF : HDFS accepte les lectures et les ecritures.
   - fsck : "HEALTHY", aucun bloc manquant, corrompu ou sous-replique.

2. Noeuds :
   - 1 DataNode actif (127.0.0.1:9866, dev-pro-ubuntu), "In Service",
     dans le rack /default-rack.
   - Capacite 467.35 GB, libre 364.61 GB (78.02 %), utilise 32 KB.

3. Repertoires :
   - Avant creation, "hdfs dfs -ls /" ne renvoie rien : HDFS etait vide.

4. Repertoire de travail :
   - "hdfs dfs -mkdir -p /retail-lake" a reussi (aucune sortie).
   - /retail-lake apparait ensuite dans "hdfs dfs -ls /".

5. Permissions :
   - /retail-lake : drwxr-xr-x, proprietaire lolorigolo, groupe supergroup.
     Le proprietaire peut lire/ecrire/entrer ; groupe et autres peuvent
     seulement lire et entrer (pas ecrire).
   - Les permissions HDFS sont actives (dfs.permissions.enabled = true).
   - Pas d'erreur de droits : lolorigolo a lance le NameNode, il est donc
     super-utilisateur HDFS.

6. Taille des donnees :
   - /retail-lake : vide (aucune sortie de du).
   - Total sous / : 0 octet. HDFS utilise : 32 K sur 467.3 G (0 %).
